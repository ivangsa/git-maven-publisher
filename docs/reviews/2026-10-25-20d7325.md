## Findings

### F1 (minor): a release repository URL with a query or a fragment makes the repository root count as every release

- **What:** `ReleaseCheck.exists` builds the URL by string concatenation, `repository.toString() + "/" + relative`
  (`ReleaseCheck.java`, `exists`). For `https://host/maven2/?sig=abc` the POM path lands in the query
  (`https://host/maven2/?sig=abc/org/acme/lib/1.0/lib-1.0.pom`); for `https://host/maven2/#x` it lands in the fragment, which is
  never sent. Either way the request is `HEAD /maven2/`. `RetentionPolicy` accepts both URLs: it checks only the scheme and userinfo.
  If the root answers 200 with a type that is not HTML (an S3-style XML bucket listing, a JSON API), every untouched `-SNAPSHOT`
  version of every touched artifact "has a release" and is deleted in one parentless commit, with no history to recover from.
  Design section 6 asks `<repo>/<groupPath>/<artifactId>/X/<artifactId>-X.pom`; this asks something else. `ReleaseCheckTest.aFailureIsAskedAndLoggedOnceWithoutTheQuery`
  even uses `?token=secret`, but its server answers 500 on every path, so it does not notice where the request went.
- **Evidence:** `core/src/test/java/io/github/ivangsa/gitpublisher/review/R42ReleaseRepositoryQueryReviewTest.java` fails for both cases:
  `[release of org.acme:lib:1.0 behind ?sig=abc (requests: [/maven2/])] Expecting value to be false but was true`, and the same for `#releases`.
- **Impact:** mass deletion of snapshot versions for a user who sets a signed or annotated repository URL. Low likelihood, irreversible.
- **Suggested task:** R42. Reject a release repository with a query or a fragment in `RetentionPolicy` (message without the value), or
  resolve the POM path against the URL's path and keep the query. Either passes the review test. Record the choice in decisions.

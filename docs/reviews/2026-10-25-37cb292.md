## Checked and found solid

- R48/D-116: a reflection probe of `ReleaseCheck.encode` on the built class gives `1.0+build -> 1.0%2Bbuild`, `++ -> %2B%2B`,
  `+;% -> %2B%3B%25`, `a%2Bb -> a%252Bb`, `a%3Bb -> a%253Bb`, `1.0 rc -> 1.0%20rc`, `a?b#c -> a%3Fb%23c`, and
  `1.0@rc,=:!$&'()* -> unchanged`. The URI constructor always quotes `%` first, and the two literal replacements cannot create each
  other's input, so a literal `%2B`/`%3B` in a name cannot be confused with a quoted `+`/`;`. A server that decodes once (S3/CloudFront, Tomcat,
  Jetty, nginx, Pages) reads the original name, and none of them decodes twice. Non-ASCII is percent-encoded as UTF-8 by `toASCIIString()` in `exists`, and
  re-parsing with `new URI(String)` does not decode. `%2B` is not on the reject lists I know of (Tomcat and Jetty reject encoded `/` and `\`; Spring's
  StrictHttpFirewall rejects `%25`, `%2F`, `%3B`, `%5C`, and a rejection there is doubt anyway). R43, R46, R47 and R48 all ran and passed in the full build.
- R49: `-Dgit-publisher.nojekyll=true` is in the Maven deploy step (`publish-maven-snapshots.yml:92`), and `it.nojekyll = true` in
  `self-publish.init.gradle:36` sets the `Property<Boolean>` `getNojekyll()` of the extension. An anonymous shallow clone of
  `zenwave360/maven-snapshots` `main` (tip 7aea3d9, 2026-10-25T19:28:12Z, core build 35) has `.nojekyll` at the root. Core writes it in `checkout()`
  only when enabled and never deletes it otherwise (`GitPublisher.java:56-57`).
- R50, the rest: D-083 and D-102 carry "Revised by D-115" notes, the workflow header no longer says "Never main", and T60 names `main` and the
  Pages URL. The design, README and AGENTS.md mention `gh-pages` only as the plugin's default branch or in generic examples, which is correct product behaviour.

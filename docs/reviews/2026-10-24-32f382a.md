## Findings

### Major

**F1. The concurrency harness rejects the collision renumbering its own design requires. (R08)**

- **What:** `ConcurrentPublishScenario.Outcome.lostFiles()` compares the original deployed path and bytes
  against the final branch (`ConcurrentPublishScenario.java:241–250`). Design §7 / D-028 requires replay
  to rename a colliding snapshot build from number 1 to remote max + 1. The recorded paths remain number 1.
- **Evidence:** new `review/R08RenumberedPublicationTest.java` starts two publications of the same snapshot
  in the same second, deploys each exactly once, and preserves the second publication as build 2 after the
  collision. Its branch passes `MetadataAssertions` **and** `assertMatchesSequentialReference` using an
  independent real Resolver replay. The subsequent `lostFiles()` assertion fails, reporting nine build-1
  paths (jar, POM, sources, and checksums), although their publication survived under build-2 names.
- **Impact:** a correct T21b/T22 publisher cannot satisfy the scenario's full consistency assertion for
  same-snapshot collisions. R04 caught collapsed publications but never proved that valid renumbering passes.
- **Suggested task:** R08. Track publication identity through validated original-to-final build mappings
  or an equivalent coordinate-scoped check that accepts permitted renames while still detecting collapsed
  publications, wrong content, and loss. Preserve the independent sequential comparison and broken-publisher tests.

**F2. Reusing a checkout directory leaves files that are absent from the branch. (R09)**

- **What:** `BareRepo.checkout()` creates directories and overwrites files but never removes old paths
  (`BareRepo.java:124–135`). Its result can contain more files than the branch tip.
- **Evidence:** new `review/R09ExactBranchCheckoutTest.java` commits `old.jar`, checks out the branch,
  replaces the branch tree with only `new.jar`, then checks out into the same directory. `readTree()`
  correctly contains only `new.jar`; the assertion that checked-out `old.jar` is absent fails.
- **Impact:** a Pages server or consumer given that checkout serves a deleted artifact. Repeated integrity
  checks can validate stale files rather than what was actually pushed, masking retention/deletion bugs.
- **Suggested task:** R09. Materialize exactly the branch tree on a reused destination, including deletions
  and file/directory transitions; retain the read/serve/404 checks and add reused-checkout coverage.

### Minor

**F3. LeakScanner copies encoded credentials into its own diagnostics. (R10)**

- **What:** encoded canaries are detected, but diagnostic labels and relative paths pass through
  `redact()`, which replaces only the raw canary (`LeakScanner.java:76,92,96,113,157–159`).
- **Evidence:** both tests in new `review/R10EncodedFindingRedactionTest.java` fail. A URL-encoded
  token used as a filename is emitted intact in `URL-encoded canary found in the name of ...`.
  A Base64 basic-auth value in `scanText`'s source label is likewise emitted intact.
- **Impact:** reporting a detected leak can itself reproduce a reversible credential representation in
  build logs, contrary to D-018/D-029. These tests use fake canaries; no real credential was exposed.
- **Suggested task:** R10. Sanitize every detected representation in source labels and paths, or omit
  unsafe labels, and verify the diagnostics themselves contain no recoverable canary representation.
